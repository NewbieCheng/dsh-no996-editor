# No996 Studio 整合方案：一个项目入口，一个通用剪辑 Agent

**供拍板，不是实施记录。** 调研基线：插件 `0.15.33`，OpenFilm `0.3.2 @ 758b1a3`，本机 DSH `0.2.2-rc.3`。本次核对了两张界面截图、仓库源码、固定版上游源码与 DSH 原生会话服务；产品行为仍以实施后的真机验收为准。

## 1. 先定产品方向

1. **图二留下，图一取消。** 「我的项目 / 示例」是唯一的项目与起步选择界面。首次没有项目、点击「新建 / 从示例开始」、在片中点「选参考」，都进入这一个原生窗口。新建空白片仍可直接开始，不强制选风格、不把依赖安装绑成进门条件。
2. **DSH 管会话，OpenFilm 管影片，No996 管产品取舍。** 保留原生 DSH 会话、模型、权限与流式工具调用。截图里的聊天列由 OpenFilm 壳渲染，不是直接嵌入 DSH Web 聊天组件。No996 自己的品牌、模板、本地环境和工作台服务留在接入层；OpenFilm 作为编辑、预览、素材库与导出的基底，不把 No996 改成官方工作台，也不复制一套编辑器。
3. **全局人设通用，口播方法按项目或任务加载。** 用户要做片就动手，问问题就回答，只改一个字号就只改一处。HTML/CSS/JS 是剪辑素材和制作手段，不是禁区；用户拿到的是项目、预览或可播放文件，不是一段替代交付的代码。
4. **免费优先，但「查到」「取到」「上轴」「看过」是四件事。** 先接通官方库中可验证的转场，跑完一支片再扩库；不把所有免费项说成完全离线，也不在缺货时悄悄改用扣费服务。

## 3. 剪辑 Agent：三层指令，各自只管一件事

| 层 | 职责 | 不放进去的内容 |
|---|---|---|
| Persona | 身份、对用户说话的方式、交付观 | 口播步骤、工具参数、具体风格、付费或依赖策略 |
| 影片预设的系统规则 | 输入分流、工具优先级、读改验流程、当前项目与权限边界 | 完整工具手册、模板文案、镜头卡全文、失效 CLI 说明 |
| 项目规则 / 按需 Skill | 用户选中的模板约束，或当前任务需要的导演、剪辑和动效方法 | 无关模板、外部示例自带指令、对普通 DSH 对话的全局影响 |

**建议人设原文**（保留现有 ≤400 B 预算）：

> 你是 No996 Studio 的剪辑与动效搭档。用用户的语言沟通。把需求变成清楚、耐看、能播放的影片；需要时用代码制作和调整画面。只问会改变结果的关键问题，如实区分方案、预览和成片。

**建议系统规则的核心段落**（实施时按实测工具名精简，不复制手册）：

> 先识别用户是要了解、制作、修改还是导出。需要动手时，先查项目、素材、轨道和现有画面，按文件类型选工具；有语言信息才转写，不把所有视频都当口播。新片或结构性改剪先做分镜，再实现；小改直接定位并复验。优先用影片工具和已验证的素材库；代码驱动的镜头，先读能控制结果的源数据和参数，做最小可检查修改。保留原始素材、锁定轨与未保存工作。实际渲染并检查后才说已预览；用户要成片时，以已完成导出和实际输出为准。

- **视频 / 音频**：先验证项目范围、媒体类型、音轨与时长。任务依赖人声时，走 `openfilm_transcribe → openfilm_storyboard(from-script) → plan`；转写时间码粗细和低置信内容如实标注。无声、B-roll、纯音乐先抽帧或读媒体信息，不硬转写。按 [转写隐私说明](<../TRANSCRIBE.md#L9-L19>)区分本机 ASR 与模型校对；建议默认本地转写不自动外送校对，若配置的是云端对话模型，需说明转写文本进入该对话会送到对应服务，不能承诺整轮完全离线。
- **字幕 / 文稿 / 图片**：文本与 SRT/VTT 先走已支持解析；只有文稿没有时间码就做分镜或待对齐草稿，不编造切点。图片按视觉能力读取，不能看图时保留素材并明确缺口。其他文件按真实支持的解析器处理，不承诺万能提取。
- **已有影片 / HTML 动效**：先 `openfilm_assets`、`openfilm_film` 和抽帧；模板体系先改 JSON、内容块、动效参数或其真正的源文件，不误改会被重新生成的产物。跨轨改动前核对保存状态；受支持的移、裁、拆优先走 [时间轴工具](<../../src/tools/clip-tool.mjs#L65-L93>) 并带基线哈希。已有分镜的 `plan` 可能返回 `missing`；不把它当创建片段接口，不把 `openfilm_draft` 当保存。要新增片段/放转场时，先验证上游保存契约；无可靠写入路径就报告缺口。
- **Skill 按需分工**：[导演](<../../skills/openfilm-director/SKILL.md>)负责需求与分镜，[剪辑](<../../skills/openfilm-editing/SKILL.md>)负责节奏、字幕和声音，[动效](<../../skills/openfilm-motion/SKILL.md>)负责定调帧、动效生产和帧检。做动效才读相关风格与镜头卡；只问身份、只改文案不启动整套生产。用户要求预览则停在预览，不强制导出。
- **模板只有一份规则源**：口播 `paper-texture` 的包内 `prompt.md` 建议写清「先按人声提时间码；保留原声主线；按句出粗剪与字幕；仅在转观点或停顿处加补画」，另三个模板各写自己的风格与素材约束。每条 ≤2 KB。新模板项目沿用现有 `.film/templates.json` 作激活状态，只在确认归插件管理的项目指令中写生成块；遇到用户自有指令不写，改为通过项目级显式读取提供有来源的规则。若当轮需要内容，用工具回执补齐，不另走浏览器 `localStorage` 或第二条隐式注入链。普通「参考」只提供资料，不激活模板、不注入下载来的 `AGENTS.md` 或 Skill。验证新会话收到正确规则、空白片不收到口播规则、别人项目不串入。

## 4. 示例、模板与扩展：复用一套窗口，保留动作的区别

| 入口或动作 | 建议行为 |
|---|---|
| 首次进入，没有项目 | 打开原生项目窗口的「示例」，并保留显眼的「空白开工」。关闭后不拦用户继续；以后不每次弹。 |
| 已有项目，点击原来的「重新选片型」位置 | 改成「选参考」，打开同一个窗口的「示例」页；顶栏项目名仍打开同一个窗口，默认在「我的项目」。不二次弹 No996 五卡窗。 |
| **参考** | 有当前项目时，沿用上游引用动作，把示例 ID、出处、可选片段和预览送入当前对话草稿；核对桥接后 DSH `prompt` 实际收到引用，不只界面显示一颗附件。不开新片、不改当前时间轴、不自动发消息。没有当前片时可先预览，再空白开工或复制。 |
| **复制** | 执行上游示例复制/导入，或调用现有 `template:create` 安装 No996 模板；都新建独立项目，不覆盖当前片。只有复制可信 No996 模板才自动启用该模板规则。失败可重试，不重复创建半成品，不切走未保存的工作。 |
| **空白开工** | 复用原生项目创建；画幅、时长、语言是可选的项目设置，不需要新增向导。模板不是打开工作台的前提。 |

- **不另造图库**：保留上游 `ProjectsPopover / ExamplesGallery` 的预览、语言和操作语义，在同一个视图里加一个窄的「No996 模板」分组。官方示例和 No996 模板的来源明确标注；归并的是用户入口，不强行把两类数据塞进同一个上游缓存。跨聊天壳和 Studio 的首次打开 / 选参考，通过现有 bridge 或窄类型回调接入，不用 DOM 查字或合成点击。旧引导、旧选片型组件及调试模板页先盘点引用，再删重复的面向用户路径；不要把上游真正用于「替换模板素材槽」的同名 `TemplatePicker` 当成废件删掉。
- **支持加包，不改写每个入口**：以上游可读取的 OpenFilm 项目目录为交换格式；No996 模板继续沿用 [模板目录约定](<../TEMPLATES.md>)，扩展有稳定 ID、标题、来源、许可、兼容版本、入口、预览及本地素材/依赖说明。先用四个现有模板和一个临时扩展包证明「加目录即可显示和使用」，移除硬编码排序对新条目的阻塞。不建新商店、不引入第二套项目格式；用户导入的项目照常打开，外部模板默认仅作素材，规则与可执行依赖不自动启用。
- **下载与创作分开**：保留原生「本地服务 / 环境」入口和 No996 已有能力。根据使用场景标明已内置、首次下载、用户自装、需账号/可能扣费；缺 ASR 只阻塞转写，缺编码器只阻塞对应导出。依赖下载安装沿明确的设置按钮或用户已选择的任务提示，不随打开示例自动启动。下载失败仍可浏览、本地建片或继续不依赖该组件的工作。

## 5. 官方免费素材：先打通一个转场，再推广

1. **检索**：修 `openfilm_library` 对固定版上游 `POST /api/get/library` 的参数适配，按实际 verb、字段类型和返回 `code` 处理。区分「未命中」与「请求失败」；从真返回取稳定 ID（如上游测试用的 `openfilm/transitions/glitch`），不猜文件路径。优先推荐贴合镜头的少量结果；没必要时保留硬切。
2. **取用**：对可落项目的内置素材复用 Studio 项目级 `saved/take` 契约，不再假设 `/api/get` 是免费取用接口。按资产类型返回素材路径、单/多片段描述、原生预设参数，或明确「仅当前 UI 支持应用」。先用返回项目相对路径的转场跑通；滤镜、内置淡化或文字样式应按上游的原生放置/预设语义分别核实，不硬写成 HTML 素材。缺下载缓存时提示；音乐和音效首取可能需要联网。有许可或来源不明的内容不打包分发。
3. **上轴**：验证相邻镜头、切点与手柄余量，按原生保存语义放置/调整。应用前报告锁轨、并发改动和不可用素材；缺少安全可复用写入时，先提供「在官方素材抽屉应用」的明确指引，不把取用回执当作完成剪辑。首批完成标准仍要求至少一个转场能由 Agent 自动上轴；需要时才加一个项目级窄操作，不做通用时间轴重写器。
4. **验证**：抽切点前、中、后帧，读回轨道位置、路径和时长；再检查导出状态和文件。运行时能搜到、模型能选择、取用有据、预览能看到，应分别有证据。免费素材链不调用收费 `openfilm_get` 服务作为兜底。官方库、[No996 风格/镜头卡](<../MOTION.md>)和项目已入库素材分别标来源：镜头卡是做法，不能把它的名字当官方素材 ID。

**动效质量基准（不绑模型）**：以用户说的「Claude 5.5 那种惊艳质感」作为审美方向，不声称等同某个模型。用两支基准片验收：一支 30–45 秒竖屏口播，卡点、字幕安全区和人声可懂优先；一支 15–20 秒横屏动效，参考示例里的动势承接而不是复刻画面，要求有主视觉、前后动作因果、至少一次有意义的跨场接力、重拍与音效对齐、无突然跳帧。交四样证据：定调帧、关键时间点的对照帧、一次素材检索→应用回执、可播放导出。用同一素材和简报对照改前/改后，不以「转场数量」评分。

## 6. 不用注入实现产品隐藏：在上游源码旁记清楚

**口径**：属于 OpenFilm 的界面差异，改固定版 OpenFilm 源码中真实的组件/渲染条件，保留原功能代码或可恢复条件，并在改动旁加短标记，例如 `NO996-UPSTREAM: hide(canvas-mode) — 产品只开放时间轴入口；恢复入口不迁移画布数据。` 注释本身不替代实现。若是禁止后端操作，另做显式服务能力控制并记录，不靠把按钮藏起来；本轮不扩大禁止范围。不修改 DSH 本体。DSH 官方插槽与必要的 `window.openfilmNative` 接入桥保留，它们不是隐藏手段。

| 差异项 | 源码级处理与恢复口径 |
|---|---|
| 第三方供应商卡片、展开按钮、音色抽屉「服务商」分组 | 在实际 Settings / Voices 组件的渲染处记录保留项和隐藏理由。不改变凭据、已装本地服务或素材库授权；能使用但不展示则标记 `hide`，不是 `disable`。音色默认视图和现有 API 响应改写分开验，不能把重写服务响应伪装成隐藏。 |
| 画布模式、社区/多余菜单 | 在来源组件显式判断入口是否显示，移除同用途的 CSS、MutationObserver 和逐项目强制写画布偏好的脚本。保留历史项目的画布数据；不恢复功能时，示例内只展示实际可用动作。 |
| 首次引导、升级公告 | 首次引导以原生示例入口替换，不接管 DOM。若保留隐藏公告的产品选择，在渲染点标注，不再通过篡写已读状态实现。 |
| 品牌、环境、账号、DSH 侧栏 | 品牌样式可继续做主题而非隐藏功能；环境/账号功能在归属组件接入，不再夹带选片界面。DSH 侧栏已有单独边界，本轮不重写，不用改 OpenFilm 源码冒充 DSH 插槽。 |

用现有 [补丁系列](<../../patches/series.json>)与 [上游同步手册](<../playbooks/upstream-bump.md>)维护：每源文件一个可重放 patch；在 [注入登记表](<../reference/injection-registry.md>)更新对应条目，记录**入口、策略（隐藏/禁用/替代）、原因、如何恢复**。上游升级先在隔离的固定版 checkout 对账/重放；若上游已有等价能力，删除本地补丁；冲突按组件重审，不恢复 DOM 兜底。不手改构建产物，也不直接覆盖有改动的上游工作树。

## 7. 实施顺序与放行条件

| 顺序 | 实施范围 | 放行证据 |
|---|---|---|
| 1 · 建基线和定边界 | 用临时项目核实示例引用到 Host、复制新建、现有模板生效点、官方库搜索/取用/应用及两类隐藏所在组件。锁定哪些入口确实要禁用，哪些只是隐藏。 | 可重复的固定版本 fixture、查明原生引用到对话及转场上轴路径；不动用户项目、会话或桌面数据。 |
| 2 · 合并项目入口 | 首次和「选参考」走同一原生窗口；融合模板分组，迁出缺依赖提示，清理旧入口及同用途注入。 | 新环境、已有项目、未保存修改、无网络和缺依赖几种场景：真机只出现一个窗口；参考进入正确草稿；复制只新建；取消不写项目；空白能开工。 |

## 8. 建议拍板的三个决定

1. **入口**：采用「图二唯一入口」，图一删除；「参考」只进当前对话，「复制」另建项目，空白开工一直可用。
2. **默认行为**：采用通用 Agent；口播规则只在内容或模板需要时加载；默认优先官方免费素材，首批只承诺验证一种完整转场链和两支基准片，不先铺满所有类别。
3. **维护方式**：OpenFilm 的结构差异走可重放源码补丁与就地注释，移除同用途隐藏注入；不因界面收拢而关闭底层能力或覆盖用户偏好。

拍板后从第 1 批开始；这份文档不授权实现、安装或发布。
