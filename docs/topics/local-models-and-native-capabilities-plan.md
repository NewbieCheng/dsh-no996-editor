# No996 工作台统一升级方案：可编辑成片、素材与本地能力

**本单仅交付方案、源码核对结果和按项验收标准。** 未安装或删除模型，未改运行代码、DSH 配置、用户项目或会话，未做桌面实测。基线为工作区 No996 `0.19.12`、固定版 OpenFilm `0.4.0 / 715c3a6`（见[状态页](../STATE.md)）、本机 CLI `dsh --version` 返回 `0.2.2-rc.5`。CLI 版本不证明 GUI 已加载某个插件或壳版本。

## 1. 产品决策与架构归属

**P0：默认交付可编辑的工程，而不只是一段能播的画面。** 主标题、辅文、标注、主要图片/头像和口播片段，凡实际用于成片，都应能按对象选中、编辑并调整大小或放大。不要求一定用 HTML、SVG、原生轨或 Canvas；自由度优先。复杂粒子、背景和连续舞台可以使用 Canvas/WebGL，前提是不把用户要调整的主体合进不可拆的像素。画布显示缩放和对象本身缩放是两个操作，后者必须持久化并反映在导出中。

| 层 | 放什么 | 放在哪里 |
|---|---|---|
| 剪辑专属预设 | 长期规则：默认保留主体可编辑；布局不等于抠像；下载需用户确认；制作交付前检查关键对象可单独选、可改、可缩放。把「持续动效」从对具体实现的强制要求调整为视觉目标，不用整屏 Canvas 牺牲可编辑性。 | [剪辑专属提示](../../src/native/openfilm-prompt.mjs)，不改 DSH 全局提示，不拼用户正文。 |
| 制作技能与导演流程 | 按需加载选型、实例和保留合成层的边界；分镜/镜头方案阶段先列「可编辑对象 / 合成层」，再生成代码。小改沿原结构，不强制重做分镜。 | [制作技能](../../skills/openfilm-motion/SKILL.md)、[模板手册](../TEMPLATES.md)及相关导演/剪辑技能。 |
| 模板、生成器与成片检查 | 把对象规则落到生成输出、稳定 ID 与可调属性；模板和自由生成共用成片检查，不能只检查提示词或模板代码。用户声明要编辑的对象缺失，须修复或经用户接受后明示限制，不把成品标为「可编辑」。 | 模板构建入口、自由生成的校验工具或生产阶段质量闸门；先做可验证的最小契约（§6.1），不另建一套时间轴。 |
| Studio、Host 与资产管理 | Studio 负责选择、右栏、覆写、撤销、渲染；Host 负责引用作用域、执行权限与版本校验、模型可用性及磁盘账本。下载授权、选中资产、抠像授权彼此独立。 | 复用 OpenFilm 舞台/Inspector 与现有原生 DSH 会话；动态素材和意图用当前作用域的结构化数据。 |

其余交付规则：

1. **模型是目录条目，权重才占磁盘。** 存储里的「不加班工作台自用」可展开，拆出「本地模型」「已下载素材 / 资源」「其他（日志等）」。本地模型明细和「服务 → 本地服务」共用状态与管理组件。在页面显示模型声明大小、当前已占用、可释放大小，三者不混用。
2. **下载并验真后，启用的是工作台内的能力。** SenseVoice 下载成功且引擎/媒体依赖可用时，在「服务 → 语音转写」出现并启用「本地 · SenseVoice」。空白设置自动采用本地；保留用户显式选择的其他引擎和「关闭」。工作台对话以及工作台字幕入口共用这个选择；不改 DSH 全局语音输入、转写设置或普通对话。
3. **网页搜索默认使用 DSH 原生工具与路由，提供显式「不加班联网搜索」。** 设置项叫「搜索来源」，不是对话模型；工作台选择实际影响原生剪辑会话的搜索调用，不改 DSH 全局设置、不静默跨服务回退。网页读取是另一项能力，不跟着搜索选项偷偷换服务。
4. **上传不代表处理授权。** 口播默认保留原背景；头像要放进影片但用途未指定时询问位置和背景。装了模型、模板推荐人像位、检测到人脸，均不构成抠像授权。原文件始终保留。

### 2.1 包体实测：随包抠像存在，不等于包体增长全来自模型

用 `tar -tvf` 列本地 `dist` 三份工件（未安装、未从 registry 验证）：旧 `0.15.33` 为 **48,895,452 B**，本次按 `.onnx/.tflite/.task/.gguf/.safetensors` 检索无匹配；`0.17.15` 为 **129,341,728 B**，`0.19.12` 为 **123,658,242 B**，后两份均含以下三权重。大小列为压缩包字节，不等于安装占用；不能把版本差全归因于模型，也不能由扩展名扫描断言没有其他分发文件。`openfilm` 是[包声明](../../package.json#L63-L82)中的固定 `0.4.0` bundled dependency，实测本地解析的依赖文件大小与后两份包成员一致。

| 来源 / 文件 | 实测或声明字节 | 存储该如何呈现 |
|---|---:|---|
| 随包 `node_modules/openfilm/models/vision/portrait.onnx`（MODNet 人像抠像） | 12,984,781 | 随包视觉模型；不可单删 |
| 同目录 `face.task`（MediaPipe 人脸关键点定位） | 3,758,596 | 随包视觉模型；不是人脸识别，也不是视频理解 LLM |
| 同目录 `person.tflite`（MediaPipe 人物分割） | 250,177 | 随包视觉模型；三权重解包合计 **16,993,554 B** |
| OpenFilm 本地服务 `libraryCache()/models/birefnet-lite/model.onnx` | 98,451,949 权重；含清单内公共 runtime 共 113,379,264 | 可下载一组；按已存在文件计实占，公共 ONNX runtime 单列且按引用计可释放 |
| OpenFilm 视觉运行器 `studioHomeDir()/cache/vision/1/` | `subject.onnx` 98,484,532；`refine.onnx` 103,885,865；`face-parse.onnx` 53,205,364（皆非随包） | 另一套按需视觉工件。`subject` 同属 BiRefNet Lite 但和上行权重字节/哈希不同，不按名字合并。还要对齐运行器可用性和未授权自下载的入口；实际存在才加总账。 |
| 工作台本地转写 | SenseVoice 239,549,735；Whisper Small/Large v3 Turbo 按固定上游清单 | 库内下载，已验证可用才显示启用；云端视觉或转写模型无本地权重不列实占。 |

**为什么旧包约 49 MB，视觉拆分后有多小**：对本地 `.tgz` 流式重压，保留原成员与顺序，仅过滤上述三权重，不安装或写发布工件。中间版 `0.16.3` 实际 120,831,083 B，移除后为 105,459,851 B；`0.19.12` 实际 123,658,242 B，移除后为 **108,288,302 B（约 108 MB / 103 MiB）**，少 **约 15.4 MB**，视觉补充包预计 **15–16 MB** 下载、约 **17 MB** 解包。旧 `0.15.33` 不含此三权重，也没把 `openfilm/node_modules` 的运行时树塞进同一个 tarball；新包这棵树约 **201.7 MB 解包**，主要是 ONNX Runtime Web 157.8 MB、MediaPipe 31.3 MB、Playwright Core 12.7 MB。另外新壳与 Studio 产物也更大。将新包的三权重与该依赖树一起过滤，得到约 **60.4 MB** 的诊断性对照，**不能当可用包承诺**：运行时可能仍要安装，少打进 tarball 不等于用户少下载，也不能直接删（会导致 Studio 无法启动）。本轮拆三权重的可用发布候选预算以 **约 108 MB** 为准，发布前重新打包实测。发布候选用[打包脚本](../../scripts/pack-tgz.mjs)同类产物做 `tar -tvf` 复核，不为取证改包或安装。模型清单维护应同时覆盖固定版 `vision-models.mjs`、`vision-assets.mjs` 与 `library/local-models.json`。

## 3. 统一模型状态和磁盘管理（任务 B：Host；任务 C：工作台壳）

### 3.1 目录与运行状态

Host 维护一个归一化模型视图。固定版上游清单和 No996 扩展清单作为输入，用稳定 `modelId + version` 映射实际 runner；SenseVoice 的大小/哈希只留一个定义源。尊重 `OPENFILM_LIBRARY_CACHE`、`OPENFILM_SHARED_HOME`、`OPENFILM_HOME` 和当前 Studio 明确传入的路径；由同一处对账，工具不二次猜路径。

| 字段组 | 建议契约（方案名，不是现成 API） |
|---|---|
| 描述 | `id, version, label, capability, sourceKind, requiredFiles, downloadBytes`；`sourceKind` 至少区分包内、可下载、外部共享；文件与可信下载源由 Host 固定清单提供。 |
| 观测 | `installState = missing/downloading/verifying/installed/incomplete/corrupt/removing/error`；`runtimeState = ready/missing_dependency/unsupported`；`bytesOnDisk, reclaimableBytes, revision`。已启用是能力路由状态，不等于文件安装状态。 |
| 动作 | 复用既有受保护的 Studio/Host 入口，需新增时才定义等价的 `list/install/cancel/remove`；操作接收稳定 ID、所见 revision，不接收删除路径、任意 URL 或凭证。返回权威快照/错误码；按现有状态通道或安装期间有限轮询，只接受更新的 revision。 |

安装必须由人点「下载／下载并启用」，显示用途、预计下载大小与是否会使用网络；只使用可信源，复用超时/切源，按模型单飞，临时文件分离，大小/哈希校验后发布 ready 标记。安装、手动预置、保留的兼容命令最终读同一份权威状态；视觉拆分不改既有语音下载与首用入口；新麦克风入口遇缺模型则指向已有安装器，不自动开麦。新视觉包无用户操作不下载；不因安装抠图或转写模型就处理已有素材。缺 Chromium、运行库、FFmpeg 等时显示具体依赖，不能显示「可用」或反复装权重。可下载但尚无 adapter 的上游模型要么标清仅支持的入口，要么不开放安装/选择；不冒充可用。

**本轮拆分仅针对三项随包视觉权重**：主插件和视觉数据包独立分发。ASR 与本地 TTS 权重不塞进主包或视觉补包、不新建语音 npm 包，已存在的下载来源、路径、安装器和缓存继续使用；存储可统一展示，不把语音迁到视觉目录。迁移期旧版包内实体继续标「随包携带 · 不可单独删除」并计实占；验过外置链路才切主包（§3.4）。未通过拆分门槛不能宣称已经减重。

### 3.2 存储口径：总账与详情用同一组字节

- 复用现有总览的项目、链接项目、导出、缓存等分类。**本地模型是「工作台自用」下的子账**，不再作为另一个顶层类别重复相加。「清理缓存」不删除模型、下载资源或用户输出。所有显示从原始字节统一格式化；说明为文件大小统计，不承诺精确等于文件系统释放空间。
- 依据清单、实际存在文件及所属根归账，模型文件/安装残留从泛扫描中排除后在模型子账加一次；可信重叠根先归一化，再按可获得的文件身份去重，不能靠文件名去重。独立副本算两份，硬链接同文件不算两次；不穿透未验证的链接或重解析点。如包内或共享路径已经计入则重分类，不额外加一次；纳入外部共享占用时显式标共享，不声称归 No996 独占、不可代删。发现扫描失败时给「部分统计/无法读取」，不给伪 0。
- 已安装模型显示实占；未下载显示 `当前 0 / 下载约 N`；失败残留和 `.part` 体现在实占或临时下载子项，但不算已安装、不可被重复扫描。资产库资源可下载部分与真正缓存分开；只有能清点并证明本工作台管理、且不破坏项目引用的资源才提供删除，无法判断引用则只展示。不要把项目资产、抠像输出、已有字幕/SRT 当模型残留删除。
- 总览显示的是各分类合计，磁盘剩余按对应根所在盘显示或明确标「项目所在盘」；模型在别的盘时在明细另列。安装、取消、失败、删除、重开触发同口径刷新；重扫不阻塞页面。

### 3.3 删除与 UI

**主入口是设置 → 通用 → 存储 → 工作台自用 → 本地模型**，无需再到服务页才能卸载。先按「语音转写／抠图与人像分割／人脸定位与解析／其他」分组，再按「可删除的下载项／随包／外部管理」筛选；全组及单项都显示实占、预计下载、可释放、状态、使用入口、所在盘与来源。状态为 `已启用/已安装未选用/可下载/不可用/随包`。同类多版本并列，不按「删抠图」一键删整类；同标签不同来源能区分。对自管可下载项在对应行提供「下载／取消／修复／删除」；明确能识别归属的失败残留用「清理残留」。设置 → 服务 → 本地服务复用同一详情与命令，并提供返回存储入口；删除后两处同步更新。删除确认写清「释放约 X；不会删除素材和字幕；以后可以重新下载」。包内、外部共享及未证明归属的条目隐藏删除并显示原因。若 OpenFilm 和插件确认共用且授权管理，界面必须告知删除会影响哪些入口。

Host 按可信清单限制路径与归属并复核目录边界，拒绝链接/异常路径；安装、推理与删除共用同一模型锁/租约。运行中返回 `MODEL_IN_USE`，先等结束或由人取消，不强删；释放缓存 runner 后删除权重、同版本就绪标记及归属明确的临时文件。并发重复请求幂等，失败刷新实际文件状态，不假报释放。删除当前选择后，保留显式意图并显示「不可用 · 重新下载或更换」，停止新任务；不静默切云端。下载回来时只有曾选择它或仍为未设置才自动恢复，不覆盖期间的新选择。

### 3.4 公共模型补充包：与主插件分发分离（任务 B2）

**推荐：同一个 npmjs.org registry，新建普通、公开的模型数据包。** 主插件仍是 `@newbiecheng/dsh-no996-editor`；首个补充包建议名 `@newbiecheng/no996-models-vision`（示例，待核对名称、scope 权限及授权）。它不是 DSH 插件、不是 DSH 组合包，不挂 MCP，不需要另建 registry。任何应用都可以按公开清单使用同一份权重；用户在「设置 → 通用 → 存储 → 本地模型」点「下载并安装视觉基础包」，查看预计大小与进度；Host 把校验后的文件写到工作台的受管视觉模型缓存（固定在当前用户的 DSH 数据目录，以 §3.5 为准；不在 `node_modules` 或 profile 安装目录），再刷新可用能力与账本。Studio 和 Agent 从统一 resolver 读取实际目录，坏包或取消不影响主插件与已装语音；不要求用户手打 npm 命令。若采用自建地址，限作大文件的静态下载源，不改 npm 安装源。补充包不进入主包的 `dependencies`、`optionalDependencies` 或 `bundledDependencies`，也不从 `postinstall` 拉取。

| 分发单元 | 放什么 | 不放什么 |
|---|---|---|
| 主插件 | UI、Host、适配器和固定版本的能力目录 | 权重、安装阶段自动下载脚本、补充包依赖 |
| 视觉补充包 | 首批 `portrait.onnx`、`face.task`、`person.tflite`，共 16,993,554 B 解包权重；配机器可读清单、来源和许可 | ONNX/MediaPipe 程序、原生绑定、安装脚本、平台缓存 |
| 既有语音下载（不拆新包） | ASR（SenseVoice/Whisper）和已有的本地语音模型沿用原下载安装器、源和目录；复用已下载文件。存储页提供状态和原安装入口。 | 不随主包或视觉包发布，不迁移下载链、不强制重下；[现有不加班配音桥](../../src/voice/voice-bridge.mjs) 是云调用，不计本地权重。 |

1. **包粒度就是下载粒度。** 首批可先出一个视觉包，按钮明确「下载视觉基础包（含抠像、关键点和分割）」并显示整包传输大小；三模型在存储明细分别可见，默认按包下载/卸载，确认框说明影响哪些能力。若产品需要「只下／只删一个」，改为一模型一包，而不是声称 npm 能只下载一个 tar 成员。大权重采用经核实可再分发的官方源或静态对象存储，目录仍统一，部署前验证实际包大小/网络限制；不为省一个包名把所有模型塞进一个大包。
2. **公共契约与版本**：数据包只放清单、权重与许可，不执行脚本。清单包含 `schemaVersion`、稳定 `modelId`、`modelVersion`、能力、相对文件名、大小、SHA-256、许可/出处及 runner/格式兼容范围。模型版本独立于插件版本；主包固定已验证的 `package@exactVersion`、tarball integrity 和文件哈希，不跟随 `latest` 或任意用户输入的 URL。下载前先审核上游权重的再分发权及附带声明；如果不能再分发，保留合法上游下载入口，不重发权重。
3. **一台机器复用，不跨账号乱共享。** 由 Host 下载固定工件，限制传输和解包大小，只解包白名单文件，拒绝路径穿越、链接及额外可执行文件；验证后才原子登记，不运行 npm 安装脚本。目标是同一 OS 用户的应用/profile 可按模型版本和校验和引用同一缓存，同版本命中不再下载；其他消费者可用同一公开包与清单。按共享引用/运行租约判定可释放空间；其他应用若不参加引用协议，按「外部管理」只读，不替它删。已合法下载且兼容的权重允许只读复用，不搬项目、不删旧包。已下载能力支持离线；没下载时普通剪辑正常、模型入口提示。
4. **先解决最容易漏的传递依赖。** 当前三权重在 `openfilm@0.4.0` 包里，[当前打包器](../../scripts/pack-tgz.mjs)把 bundled 依赖树整棵带入，[Agent 视觉桥](../../src/tools/vision-browser.mjs#L93-L103)也直接读包目录。只从主包 `files` 排除或把 OpenFilm 从 bundled 改成普通依赖，都可能仍在安装时拉回原权重。先核对 OpenFilm Studio 视觉入口和 Agent 入口，改用同一个 resolver；优先等/推动可固定版本、正式发布且不带权重的 OpenFilm 分发，或另行评审源码级薄运行时（许可、可重现构建、来源明确、平台回归）。不就地修剪已安装依赖，不以删文件假装修复，不未经评审改用第三方替代包。若上游薄分发暂不可行，模型目录/下载管理可先做，**真正拆包要单独标未达标**。
5. **切换与发布顺序**：用本地测试工件完成清单、resolver、安装及旧包读路径兼容；检查主包 tar 列表及干净 profile 的完整依赖树和首次启动下载记录，双重确认三权重没有被间接带回。获明确授权后，先发布并核验公开补充包的固定版本与完整性，再发布依赖其目录入口的主插件。旧用户短期保留已装能力，迁移不静默下载；回退主插件不删除模型缓存或项目。正式主包仍遵循[发布手册](../playbooks/publish.md)。

### 3.5 从 0.19.x 升级：主插件覆盖重装，模型不重下

**版本目标：从 `0.19.x` 升级到 `0.20.0`**，如该版本已占用则由维护者确认递增替代号。`0.2.0` 不是这次发布号。本计划不改版本号也不发包。视觉补充包独立版本，不随主插件版本号递增；同样权重沿用同一固定补充包版本，无须反复发布。

#### 放在哪里、什么时候复用

- **持久目录**：当前 OS 用户下的 `$DSH_HOME/no996-openfilm/model-store/vision/`（没有设置 `DSH_HOME` 时按现有 Host 的默认用户数据根解析）。具体工件按稳定 `packId` 和已验证的权重清单哈希分目录，索引与就绪标记同样放在该用户数据目录；临时目录只容纳下载中内容。绝不以 `node_modules`、插件安装目录、profile 的包管理子目录、项目目录或 npm 暂存缓存作为正式存储。安装详情显示实际路径和版本。这个目录只保证在同一用户数据根下复用；主动清空 DSH 用户数据、更换电脑/用户或换数据根不等于普通插件更新。
- **启动/重载顺序**：Host 和 Studio 共用一个 resolver，先读本地库、核对清单身份与运行时兼容性；初次纳管、文件签名变化或标记无效时，以实际文件大小和固定哈希复核，不仅凭索引说已装。不用请求 npm 判断已装，也不在启动/插件更新/重载时后台拉权重。同一权重、兼容 runner 且校验通过，显示「已安装 · 本地复用」，离线也能用。版本号变化但权重字节完全相同（例：只改许可说明或清单文案），经固定目录映射验证后可复用；真正更换权重或不再兼容才在用户使用时提示更新，展示原因和下载量，不静默覆盖兼容旧版。缺失和损坏分别显示「去安装」和「修复」，仅在用户确认后取包；并发两个 profile 共享单一安装锁。
- **卸载边界**：DSH 的停用／移除／卸载重装只清插件自己的运行资源，不清持久模型库；实现者要在目标 DSH 实测实际更新流程，不能假定每个版本行为一致。模型库清理由存储页显式「卸载视觉基础包」触发，受共享引用/运行中任务约束；不得跟随项目缓存清理或升级动作。ASR、已有本地语音继续用原目录和下载器，不与该视觉库绑定。三项指抠像、人物分割、人脸关键点定位，不是换脸模型。

#### 0.19.x 的两种来源要分开迁移

1. **之前已下载到用户数据目录的文件**：升级首次打开时只读探测受信旧视觉目录；确认就是所需模型（哈希、规格、可再使用许可）才通过本地导入/登记纳管，无网络重下。不因模型名相同而复用不同文件；语音旧缓存继续直接使用。迁移失败保留原状态，可重试，不删原文件。
2. **旧版权重只在旧插件目录**：如果 DSH 更新先卸载旧包，新版本启动时旧路径可能已消失，不能承诺事后找得回来。要兑现从 `0.19.x` 零网络重下，**旧包仍存在时**先保存未保存编辑、按发布手册备份 profile，再走受支持的迁移入口：优先让仍装着的 `0.19.x` 运行与发版配套的只读预迁移工具，或先通过官方允许的过渡版本/入口导入到上述持久库；入口须在卸载前实际可用，不能要求用户先卸载才能拿到。迁移只读取固定旧权重文件，逐文件验证再原子复制/登记，给「已保存 3/3、可更新」回执；不修改旧安装树，也不搬项目和会话。若旧包已卸载，允许用户从安全的备份或仍持有的受支持旧工件按白名单导入；两者均不存在才提示一次正常下载。这一步是首轮拆包迁移，后续升级不需要重复。
3. **正式升级顺序**：保持旧版可用 → 按上两类保存/识别可复用权重 → 经授权按 [发布手册](../playbooks/publish.md)发布并验证固定视觉补充版本 → 发布递增主包 → 在 DSH 更新（如果该版本需要先移除再安装，照实走该流程）→ 整应用重启 → 打开「存储 → 本地模型」确认「本地复用」并试用。普通使用不依赖视觉包。回滚主插件不能清除持久模型数据。若目标 DSH 无法提供可行的预迁移入口，发版说明必须直说哪类旧用户可能需要一次下载，不能把全部用户零下载当已验收。

#### OpenFilm 内的升级提示、下载入口与自动切源

**只提醒缺的包，不让所有升级用户重下。** 从 `0.19.x` 升级到此次拆包版本（npm 建议 `0.20.0`），首次打开「视频创作」时先由 Host 本地核对/导入可复用权重，再决定是否显示提示。不要在检测中显示「请重新下载」，不要为了检测联网。

| 入口 | 行为与文案 |
|---|---|
| OpenFilm 工作台内容区顶部 | 校验后仍缺视觉包，显示可关闭、不挡项目的一次性提示：「新版已将本地视觉模型改为按需安装。普通剪辑和语音转写不受影响；使用人像抠像、人物分割或人脸关键点时，可安装本地视觉组件。」提示旁显示 Host 计算的实际需下载大小（只缺权重时约 15–16 MB；若还缺运行时则按实际工件合计）。主按钮「查看并安装」，次按钮「稍后」。主按钮打开对应包详情，由用户确认下载；有备份另给「从本地导入」。迁移成功或缓存有效不提示，不能把「已升级主包」当缺模型；关闭后同一次拆包升级不重复弹，别复用通用更新公告强弹。 |
| 设置 → 通用 → 存储 → 工作台自用 → 本地模型 | 永久管理入口。分为「视觉补充包」和「既有模型」：视觉基础包列出三项能力和同一套下载/卸载状态；SenseVoice、Whisper、OpenFilm 可下载的 BiRefNet 等各归原能力分类和安装器，明确其来源，不把现有 BiRefNet 或语音当作视觉基础包的替代品。设置 → 服务 → 本地服务同步显示，指向同一项详情，不重复安装。 |
| 首次点击依赖该包的功能 | 只拦截这项功能，提示「需要视觉基础包」「重新校验／修复」或跳转安装进度；没有用户确认，不后台取包。安装成功即刷新能力和存储，允许用户重试原动作，不自动应用抠像或改时间轴。兼容旧版仍可用时，不因出现新目录版就强制升级。 |

**自动切源仅在用户确认下载之后执行。** 新视觉补包用可信目录固定 `packId`、版本、预计传输大小、工件完整性和逐文件 SHA-256。同一版本的候选源默认「已预先验证的国内镜像 → npmjs.org 官方固定版本工件」，国内镜像未核验或未配置时直连官方；可在失败详情里提供「改用官方源重试」。镜像必须提供与官方完全一致的 tarball，不允许通过镜像切换版本，不要求用户改全局 registry，不探测地理位置。对 404/镜像未同步、连接失败、限流、停滞或校验失败自动切下一个可用源，每次显示「正在连接／下载／切换来源／校验／安装」；复用 [下载停滞监测](../../src/host/download-stall.mjs)，默认约 20 秒连接超时、30 秒无新字节才切源，下载持续有进展不强杀。切源不混用不同来源的半包；取消就停止整条队列，两源均失败则保留已经验证的旧版、清理或归账临时文件，提示「重试／导入本地包」，不标已装。最终校验后原子写入 §3.5 的持久库；多个页面同时点只启动一个下载。**既有语音及 OpenFilm 其他模型继续走各自现有下载源、镜像策略和存储目录，不被新视觉安装器接管。**

**代码落点**：在固定 OpenFilm 壳的工作台通知区复用 `apps/desktop/shell/EnvironmentNotice.tsx` 的展示位置或同层新增窄提示；不要改 DSH 通知中心。设置端在固定上游 `StorageGroup.tsx`、`LocalModels.tsx` 接同一 Host 快照与深链；[Studio controller](../../src/studio/studio-controller.mjs)装配本地 resolver、迁移探测与视觉包下载器，通过[页面门面](../../src/official/official-facade.mjs)只暴露稳定 ID 和进度/动作；来源列表和路径只由 Host 控制。按「本地探测 mock → 提示/双入口 → 两源失败切换和完整性 → 卸载重装桌面验证」实施。

### 3.6 0.20.0：分包边界、第三个可选项和通用安装

#### 组件怎样呈现：两条 DSH 组件 + 一个可选能力，一键安装

当前[插件清单](../../cordis.patch.yml#L1-L18)的两个顶层条目是工作台与剪辑 Agent 预设，截图里「包含的组件」是 DSH 的加载项，不是 npm 依赖或下载文件的列表；截图来源为 `file:` 开发包，只能用来定位界面，不能当作正式升级证据。Windows 本机 DSH `0.2.2-rc.5` 的 Client Inspect 实测 `plugins.bundle.config` 由本插件占用，位于说明与原生组件行之间；[现有注册](../../src/studio/studio-entry.js#L153-L170) 按包名挂载剪辑环境。[插件环境区](../../src/ui/env-section.mjs) 可以直接追加「可选组件 · 本地视觉」；也可用已确认的 `plugins.detail.section` 追加独立区域，但必须精确过滤 `subject` 为 No996，优先复用现有区域，不替换 DSH 列表或注册同一 slot key 两次。

**不建议把第三项做成 DSH Loader 行或再做一个 DSH 插件。** 权重和浏览器运行时文件不是独立 agent/plugin，强行注册第三行会把安装、开关和失败状态与 DSH 插件混在一起。用户实际看到三项能力：工作台、Agent 预设、**可选组件：本地视觉**；前两项仍由原生「包含的组件」显示，第三项是独立卡片。插件详情卡显示「未安装／可导入／部分已就绪／已就绪／需修复／运行异常」、实际磁盘和缺失部分，提供「安装本地视觉／打开管理」；OpenFilm 的升级提示与存储页通向相同 Host 安装计划。详情页无可验证的直接下载桥时只提供打开工作台的入口，不复制安装器；整组开关和卸载行为不变。

#### 下载编排：一次确认，只取缺的工件

1. Host 根据固定工件清单和本地已校验文件生成安装预览：三项能力、已复用部分、需下载的每个工件、预计合计和所需磁盘（考虑暂存+安装）、来源。通用视觉数据和 JS/WASM 包不按系统或 CPU 架构设安装白名单，不因为某个环境尚无测试记录就拒绝下载；只缺权重、只缺运行时或两者都缺分别显示。下载确认传稳定 `capabilityId + planRevision`，不由页面提交路径/URL；确认时重算，工件列表变化后重新确认，不静默追加语音或浏览器的额外下载。
2. 用户点一次「安装本地视觉」，Host 对已校验件直接复用、只下载缺件。沿 §3.5 的已验证国内镜像 → 官方固定工件协议，逐工件校验下载与展开；单飞任务跨详情/存储页显示同一进度。各件验证后原子写入持久库并独立持有版本；一个失败时保留其他已验组件和兼容旧版，但**整项不标可用**。取消不触发下一工件或镜像；重试只补失败/缺少项。磁盘不够、代理/网络、错误包、版本不支持、设备运行失败分别回显，能退回旧可用版本才使用，不静默重下或切云。
3. 安装后以版本配对做能力探测：能取正确文件且实际 runner/browser 能加载才 ready（文件在磁盘但 WebGPU/WASM 路径失败未就绪）。若支持非 GPU 路线，按已测能力回退 CPU/WASM；不假设某个型号或宿主默认支持。探测只用本地非个人 fixture，不运行用户素材、不自动抠像。坏模型能单独修复，不将原录音/素材送到下载服务。

### 4.1 聊天输入框右侧：录音 → 本地转文字 → 草稿

- **按钮**：「语音转写」麦克风图标，放在截图对话输入框最右侧、现有发送/停止键左边。保持发消息键和停止生成键原义；收窄时仍可键盘唤起、可见录音指示和停止/取消。无项目时不可录，空白但可写的剪辑对话可录，不为录音新开原生模型回合。
- **状态流**：点击先查工作台本地模型可用性；有可用模型就使用用户库内**同一份权重**，不重新下载。没有时显示现状及「选择模型／下载并启用」和到存储详情的入口；安装完成让用户再次点录音，不自动开麦。权限批准后才开始采集，停止后转写，**追加到原会话最新草稿的末尾**（不依赖光标或选区，保留原文、格式和附件引用），用户确认后自己按发送；取消、权限拒绝、识别失败均不覆盖草稿。切对话、关闭、超时取消或隔离原会话结果，绝不写错草稿；录音结束及时释放设备。录音仅临时使用，不默认入素材库、写字幕或上传云端。需要对某段口播录音或视频产字幕时走「转写所选素材」入口，使用同一离线能力选路和时间码流程，不混成录麦。
- **默认本地且可解释**：根据已选且支持听写的本地模型执行；媒体端显式云选择不得把麦克风录音送云。若媒体配置选云，听写按钮提示选择本地而不是无声切换；两入口可共享库和本地 runner，按媒体/听写各自输入能力决策。首档停录后回填，不承诺实时逐字。音频可按已实现 runner 输入规范录成有上限的 PCM/WAV，或走已验证的解码层；保留普通发送功能，取消和拒绝不触发后续模型操作。

### 4.1.1 追加协议：编辑器负责追加，小模型只负责识别

**开工硬要求：已有文字只增不改。** 例如已输入「帮我把口播剪到 30 秒。」再说「结尾加一行字幕」，结果应为「帮我把口播剪到 30 秒。结尾加一行字幕」。哪怕点击麦克风前光标在句中、选中了原文、或录音期间继续打字，也追加在结果回到时的**最新草稿末尾**。已有内容一字不动；边界仅按需为英文词补空格，保留已有空白/换行，不重写用户标点。连续录两次按已完成的两次操作追加，支持撤销最后一次追加，不撤掉之前手打内容。

1. **编辑器事务**：固定上游 `apps/desktop/chat/src/components/prompt-editor/PromptEditor.tsx:454–490` 的 `setText()` 会重渲染内容，现有 `insertText()` 按当前选区写入，不能直接用于尾追加。在 `PromptEditorHandle` 增设等价的 `appendDictation(text)`，在一次 Lexical 更新中读取最新编辑器树、明确选择文档末尾、写入纯文本节点并留一条独立撤销记录。不能拼录音开始时的整段快照再覆盖草稿，也不能解释转写结果里的 `@`、`/` 或看似引用的符号为命令/pill。不删除原有引用节点。中文输入法正在组字时等 `compositionend` 再追加，不打断候选。
2. **回执归属**：每次听写带唯一 `captureId` 与 `(projectId, conversation, draftGeneration)`；同一草稿一次只跑一个录音/识别任务。手工编辑不改变草稿代次；提交、清空重置、切项目/会话或销毁后旧回执不回填。结果允许应用一次，重复回调不重插。取消、权限拒绝、静音、空结果和失败均不修改草稿或启动 Agent；用户点发送前只更新草稿，不提交消息。
3. **小模型契约**：输入仅录音及必要的语言/格式参数，不把已输入的提示词或附件交给模型。Host adapter 只返回本段纯文本与必要状态，不负责组织整条消息、补写意图或执行命令。先验证用户选的模型版本/运行时确实支持听写与目标语言；SenseVoice 是现有可接入口，不硬编码替换用户选择。首期停录后一次回填；静音/空结果显示「未听清，重录」；没有供应方置信度就不伪造分数。错字、方言和中英夹杂允许用户发送前修正，不偷偷调用云模型润色或补词。实施回执记录实际模型 ID、输入格式、支持语言与短录音样本的识别限制，不把小模型准确率宣称为和 DSH 一致。
4. **DSH 对标**：用同一份初始草稿、同样的点按和第二次录音，在普通 DSH 与工作台分别记录「开始／停止／回填／是否发送」。交付要求交互对齐；若原生接口不可复用，只替换识别接入，不改变本节的末尾追加规则。结果文本或时延不同需如实标明，不以「一模一样」掩盖引擎差异。

### 4.2 DSH 原生听写的复用门槛

## 6. 资产使用、口播与头像（任务 F）

资产生命周期是「目录项 → 用户取用或导入 → 项目素材 → 片段/画面层」，不是同一个可删除对象。用户选择某资产时先显示可用、需下载、下载中或失败；只有点击明确的「下载／下载并使用」才搬文件，成功后才能引用为项目内文件或上轨。一个素材被多处复用时，改画面层仅改变实例，不替换素材原件；从片段移除不等于清理缓存或卸载模型。删除已下载资源按 §3 的管理归属和项目引用检查，不删除已用素材。工作台可根据所选口播提供「生成字幕」，但这一动作不触发去背景；头像的布局、去背景也是两个独立选择。

| 用户输入/操作 | 默认行为 | 后续允许 |
|---|---|---|
| 上传口播，「帮我剪/做字幕」 | 原图入剪辑，保留背景；裁切和排版不等于抠像。无需为保背景弹窗。 | 可做转写/剪辑，不自动调用抠像、下载抠像模型或在片段上加蒙版。 |
| 用户说「去背景／抠出人物」或点对应动作 | 字面明确可进入该素材的抠像意图；工具缺能力才提示需下载。 | 图片预览可先出透明副本。口播视频须区别「看一帧预览」和「应用到整段」；当前已知 Agent 工具仅单帧。未证实存在连续视频处理时，只给单帧预览或解释限制，不能贴静态蒙版假装整段完成。 |
| 只传大头照或拿来问答 | 不默认当作影片素材、不擅自抠图或上轨；若未表达制作意图且没有明确问题，可问「这张照片要用于影片吗？」 | 用户决定用途后按实际请求继续。 |
| 做片中用户新增头像且用途/位置不明 | 在进行该素材布局前问一次：「这张头像做全屏介绍，还是放右下角做画中画？背景保留（默认），还是去掉？」可加「其他位置」和「先不放」。 | 可继续不依赖头像的步骤；确认后按画幅给预览，处理安全边距、字幕避让；位置选择不会自动勾选去背景。 |
| 「头像放右下角，保留背景」或已有同素材明确选择 | 不重复问，按指令执行。 | 模板只提出槽位建议；同一素材的新显式指令优先，换素材不复用旧授权。 |

**实现分层**：

- 长期行为放在剪辑专属[预设提示](../../src/native/openfilm-prompt.mjs)和相关[制作技能](../../skills/openfilm-motion/SKILL.md)；替换含混的「overlaying 时用 cutout」指令，明确「布局先于处理，未指定就保背景」。模板只存可选的人像槽位/建议布局（例如右下角、安全区），不授予抠像权限，不往用户正文、通用 DSH 系统提示或旧项目指令里拼规则。
- 当前素材事实和已选意图走既有会话作用域上下文。不把模型自动判断写成用户授权。若人明确说了位置/去背景，可让 Agent 预填提议；对有副作用的 Agent 抠像/应用，通过工作台受信任的用户动作确认（聊天内操作卡或编辑器动作），用户不需重输，默认剪辑继续。手动编辑器明确点击可直接视作该次明确操作。确认记录绑定 `(projectId, conversation, assetId, operation, sourceRevision)`，区分预览和应用、单帧和整段；拒绝模型自行填写 `confirmed=true`、引用别的对话/素材，或复用模板推荐作为授权。保持工具执行面权限校验，预设不替代权限。
- 核对实际会写透明结果或对时间轴应用抠像的所有入口（视觉工具、上游编辑器、媒体网关、模板快捷应用）；对话链上统一执行条件。未授权：返回需要确认，既不运行抠像也不改项目。仅合法预览：生成派生素材，不替换原件，不自动应用到时间轴。应用用版本守卫写指定片段且可撤销；拒绝旧 revision。保留原始画面与项目里的历史变更，不批量清理。

### H1：生成契约、可调字段与交付门槛

1. 生成前为主体列出**稳定 ID、类型、镜头归属及可编辑字段**。可以是同镜头内 HTML/SVG 层、原生片段或字幕轨；独立拖动时间才额外上轨。主标题/辅文/标注提供文字、字号、颜色、位置和缩放；图片/头像/口播片段提供位置、尺寸/缩放、显隐和适用的替换/裁切；不要求字字独立或任意矢量路径编辑。对高频项用 `data-props` 直达右栏，图层从预览或图层树可选。标题在特定时刻才可见时，不跳选其他同名对象。
2. `clipId + elementId` 单实例定位，ID 不从当前文案、序号、坐标或随机数推导。编辑的唯一权威为 Studio film 实例覆写；模板/镜头源码是默认值。生成器、重编译和 Agent 修改必须保留已有覆盖；不能匹配时显式报冲突。不建立与原生 timeline 双写的编辑 sidecar。布局外层与动画内层分离，以免放大/移动把原动画 transform 干掉。
3. 首期交付独立文字的原生入场/循环/出场，以及镜头内关键标题的受控动效预设和时长。使用已声明的 CSS 变量或原生片段；若现有变量控件不适合才加受控下拉，禁止把任意 JS 作为右栏值。预览、寻帧和导出使用同一影片时间；第二批才扩充可验证的数值关键帧，补转场、切分和非零源时间。复杂粒子、背景、连续画笔或物理表现可作标明的合成组，只开放实际能调的参数，不使用 OCR 或透明占位层伪造可编辑。
4. 对模板与自由生成统一做两层检查：**生成后**核对运行时能找到真实对象、ID 唯一、类型和可调项一致；**交付前**实际改变关键对象的位置/缩放与一项内容或样式，核对同一对象的渲染和覆写（自动化在临时副本，用户工程不被测试改写）。用户指定的主体不能编辑时优先改结构，必要时请用户选择是否接受合成层例外。校验不强制普通问答、小改走完整流程，也不为非导出请求强制导出；实现验收用固定 fixture 对比导出。

| 素材库文件 / 已导入口播或头像 | `projectId + assetId + sourceRevision`。可预览、引用或放入工程；仅选中不下载、不插轨、不转写、不抠像。未下载的目录项由人点取用，下载与入轨是否绑在一次动作要在按钮上明示；不可把远程 URL 视为项目内文件。 |
| 时间轴片段 / 画面内部层 | `projectId + clipId + elementId（选层时）+ revision`。面板分别显示「片段」和「镜头 › 具体层」，支持右栏与拖拽改对象，不扩大整个画幅；同源复用只改本实例。选了预览对象不等于选中素材原件。 |
| 引用到原生剪辑对话 | 在上述目标上绑定当前 `conversation`，走原生 `StudioRef`/现有通道；标签回跳同片段/层，匹配不上请重选。Host 复核范围、版本和唯一性，不从标题字面、矩形、临时 handle 或第 n 个元素推断写入目标，不拼入用户正文。引用不代表下载或抠像授权。 |

手动编辑与 Agent 写入统一走 Studio `/api/projects/:id/edit` 的修订与 history/undo；扩展受限层编辑入口，不把 [现有 `.t` 写法](../../src/tools/clip-tool.mjs#L192-L207)当任意镜头接口。验证上游真实 `base` 冲突语义，不能只在客户端比版本；整组覆盖替换无可靠 CAS/字段合并则不开放该写操作。锁轨、重复 ID 或同字段竞争须拒绝，不吞掉用户调整。对话 UI 负责引用选择，Host 只提供已授权任务；素材或模板不能自行触发下载/抠像。

### H3：旧片兼容

不开启自动迁移。老片已有真实层就用原生选择/覆写；有源 Canvas 片仅在用户明确要求后复制试点，关闭被提取文字的原绘制避免重影。只有成片、没有可关闭的原对象时，只能重做该镜或加新的覆盖层；说明原字不能独立编辑。
