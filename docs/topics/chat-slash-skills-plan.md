# 剪辑聊天栏 `/` 技能菜单接入 DSH：实施方案

> 历史方案，以下描述的是改动前的问题和目标，不是现行接口。实际接入为「剪辑预设同源内置目录 + OpenFilm 已安装」，经 Host 校验后写入当轮上下文；没有实现 DSH 原生调用、运行时目录或安装 UI。见[现行架构](../ARCHITECTURE.md#23-聊天桥实时模式和显式技能)和[验收状态](../STATE.md)。

范围：剪辑聊天输入框的「＋ → 技能」、输入 `/` 和选择后发送。核对基线为 DSH `0.2.2-rc.5`。

## 为什么现在没有列表

- OpenFilm 上游 `ChatPane` 通过 `app.skills.list(project.path, agent)` 加载候选。该接口报错时被捕获成空，菜单仍能打开，所以看起来像是没有安装技能。
- [内嵌兼容桥](../../src/official/official-facade.mjs#L667) 当前把 `skills.list` 和 `skills.texts` 放在统一拒绝的占位方法中，没有接到 DSH。剪辑预设的 [技能注册](../../src/native/openfilm-skills.mjs#L27-L49) 则是另一条链：模型能调用技能，不代表界面能列出它们。
- 仓库目前包含导演、剪辑、动效、Vibe 制作四个内置技能；最终菜单以当前剪辑会话可供用户调用的实际目录为准，不硬编码四条，不放开全局技能目录。

## 如何接通

1. **目录从 DSH 读。** 在现有官方壳 RPC 中增加专用列表操作（建议 `skills:list`），参数是 `projectId + conversation`，不信任页面提供的目录或原生会话 ID。Host 验证项目归属，使用现有会话映射取得该剪辑会话的技能视图。运行时已核对 `skills.snapshot({ scope, cwd, signal })` 与 `invocation.userInvocable`；原生 scope 获取方式须用实际运行时确认。只回稳定技能名、标题、描述；区分加载中、可重试错误、确实为空。菜单打开不得执行模型或静默创建持久会话：还没有原生 Agent 时，先确认能否读取预设视图；若不能，列表仅展示插件同源内置注册元数据，并在首次发送时用新建的目标 Agent 复核。禁止退回普通 DSH 全局目录。
2. **选中是引用，发送才调用。** 在 OpenFilm 上游聊天源码复用现有技能选择弹层和引用标签，`/` 与「＋ → 技能」走同一个入口；支持键盘搜索/回车、鼠标点选、移除标签。选中只更新当前草稿，不后台发送。明确点发送时，把技能 ID 作为结构化字段随本轮发送；例如选中「导演设计」再写「帮我给这段口播做分镜」。切换项目或对话后丢弃迟到目录回执，不串用旧草稿的技能。允许只发送技能与否，以 DSH 的原生调用契约为准，不偷偷补造用户正文。
3. **真正走 DSH 调用，而不是把名字或全文塞进用户消息。** 当前 OpenFilm 默认发送链通过 `skills.texts` 把文本追加到模型输入；剪辑预设不沿用这条做法。实作前先核对本机 DSH Composer 的原生技能提交契约和 Host 入口；`skills.get()` 只是取定义，`commands.execute()` 是另一套命令协议，二者都不能因为名称相似就当成原生技能调用。若现有版本没有可复用的提交入口，则通过 Host 按真实 Agent scope 重新查 `skills.get` 并检查 `userInvocable`，再经已验证的请求级扩展把技能作为当轮独立上下文，不改用户正文、不改变全局提示、不绕过工具权限。若也无可靠的当轮扩展，报告不支持，不把「选中了」冒充「调用了」。技能移除、禁用或被替换时保留草稿并提示重新选择，不能静默降级为普通发送。
4. **源码落点。** 前端改 OpenFilm `apps/desktop/chat` 的输入区和发送链，通过 [上游补丁流程](../playbooks/upstream-bump.md) 重建；兼容桥改 [官方门面](../../src/official/official-facade.mjs) 和 [对话 RPC](../../src/official/official-chat-rpc.mjs)，会话定位复用 [原生会话服务](../../src/native/dsh-native-agent-service.mjs)。不新增 DOM/CSS 注入，不改 DSH 本体，不把整个命令注册表暴露给 iframe。

## 验收

- 已有对话和空白对话都能用 `/` 或「＋ → 技能」打开同一目录；未加载、真正无技能、服务失败三态可区分；浏览不会发模型请求。
- 选技能、附带自然语言后发送，mock 能证实实际应用的是当前会话的技能；用户气泡保持原文和引用标签。只打开、选中后移除、取消发送均不调用。技能失效时提示并保留输入，非用户可调用技能不显示且 Host 拒绝。
- 用 mock 验证切对话竞态、项目归属、模型请求入参及重复发送防护；重建本地开发壳后，在 DSH 桌面测试项目验收菜单和调用链，不触碰用户既有项目或历史。
